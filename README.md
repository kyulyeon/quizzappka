# 유하경 능력고사 · 실시간 퀴즈 (Kahoot 스타일)

호스트 1명 + 시청자 N명이 **링크 하나로** 같이 하는 실시간 퀴즈입니다.
문제당 **15초** → 자동으로 **정답 공개** → 서버가 **채점** → **최종 순위 + 누적 명예의 전당**까지 자동.

- 시청자는 **링크 접속 → 닉네임 입력 → 끝** (호스트가 이름을 추가하지 않습니다)
- 응답·점수·참가자 목록이 **실시간(WebSocket 방식 스트림)** 으로 반영됩니다
- 정답은 **공개 시점에만** DB에 기록되므로 참가자가 미리 볼 수 없습니다
- 방송이 끝나면 누적 점수가 `명예의 전당`에 쌓입니다
- GitHub Pages 에 그대로 올릴 수 있습니다 (서버 코드 없음, 무료)

## 1. 준비물: Firebase 무료 프로젝트 하나 (5분, 한 번만)

> **"Firebase Realtime Database URL"이 뭐냐면** — 구글 파이어베이스가 제공하는 *데이터 저장소 인터넷 주소*입니다.
> `https://내프로젝트-default-rtdb.firebaseio.com` 처럼 생겼어요.
> **직접 찾아서 복사할 필요 없습니다.** 아래 2단계에서 설정 코드를 통째로 붙여넣으면 앱이 자동으로 뽑아 씁니다.

### 1단계 · 프로젝트 만들기
1. https://console.firebase.google.com 접속 (구글 계정 로그인)
2. **프로젝트 추가** → 이름 아무거나(예: `hakyung-quiz`) → Google Analytics는 꺼도 됨 → **만들기**
3. 왼쪽 메뉴 **빌드 → Realtime Database** → **데이터베이스 만들기**
   - 위치: 아무거나 (예: `asia-southeast1`)
   - 보안 규칙: **테스트 모드로 시작** 선택 → **사용 설정**
4. 화면 위쪽에 `https://xxxx-default-rtdb.asia-southeast1.firebasedatabase.app` 같은 주소가 보입니다. (이게 DB 주소)
5. 왼쪽 메뉴 **빌드 → Authentication** → **시작하기** → **Sign-in method** 탭 → **Anonymous(익명)** 클릭 → **사용 설정** → 저장
   > 이걸 안 켜면 `익명 로그인이 꺼져 있습니다` 오류가 납니다. 참가자 구분에 꼭 필요해요.

### 2단계 · 설정 코드 복사 (붙여넣기용)
1. 왼쪽 아래 **⚙ 프로젝트 설정** → **일반** 탭
2. 아래로 스크롤 → **내 앱** → 웹 아이콘 `</>` 클릭 → 앱 이름 아무거나 → **앱 등록**
3. **SDK 설정 및 구성** 에서 **구성** 라디오 버튼을 고르면 아래처럼 코드가 나옵니다:

```js
const firebaseConfig = {
  apiKey: "AIzaSy....",
  authDomain: "hakyung-quiz.firebaseapp.com",
  databaseURL: "https://hakyung-quiz-default-rtdb.asia-southeast1.firebasedatabase.app",
  projectId: "hakyung-quiz",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```

4. **이 블록 전체를 복사**하세요.

> ⚠️ **`databaseURL` 줄이 없어도 괜찮습니다.**
> Realtime Database 를 나중에 만들면 설정 코드에 그 줄이 안 들어있을 수 있어요. 그런 경우 앱이 `projectId` 를 보고
> `https://프로젝트ID-default-rtdb.<리전>.firebasedatabase.app` 을 **자동으로 찾아서** 연결합니다.
> (그래도 안 되면 Realtime Database 를 만든 뒤 설정 코드를 **다시 복사**하면 `databaseURL` 이 포함됩니다)

### 3단계 · 호스트 화면에 붙여넣기
1. 퀴즈 사이트를 엽니다 (`index.html`)
2. 오른쪽 위 **설정 (S)** 클릭
3. 방금 복사한 코드를 **그대로 붙여넣기** (`databaseURL`, `apiKey` 두 줄이면 충분)
4. 세션 코드 입력(비우면 자동 생성) → **연결하기** → 새로고침되면 오른쪽 위 **`실시간 연결`** 이 초록색

### 4단계 · 보안 규칙 넣기 (꼭 하세요)
1. 이 저장소의 **`firebase-rules.json`** 파일을 열어 내용 전체 복사
2. Firebase 콘솔 → **Realtime Database → 규칙(Rules)** 탭
3. 기존 내용을 **전부 지우고** 붙여넣기 → **게시(Publish)**

이 규칙이 하는 일:

| 규칙 | 막아주는 것 |
|---|---|
| `state / scores / results / final` 는 **호스트만** 쓰기 | 시청자가 점수를 조작하거나 문제를 넘기는 것 |
| `answers` 는 **본인 것만, 1문제에 1번** | 정답 공개 후 답을 바꾸는 것 |
| `answers` 는 **제한 시간 안에만** (`now <= 시작시각 + 15초`) | 시간이 지난 뒤 몰래 제출 |
| `answers` 는 **호스트만 읽기** | 다른 사람 답을 훔쳐보는 것 |
| `players` 는 본인 닉네임만 | 남의 이름 바꾸기 |

> 규칙을 안 넣어도 게임은 돌아갑니다. 다만 **아무나 점수를 바꿀 수 있는 상태**이니 방송 전에 꼭 넣어 주세요.
> (규칙 파일: `firebase-rules.json` — 내용은 같습니다)

## 2. 방송 시작하기

1. 호스트 화면에서 **새로 시작하기** (Space)
2. 오른쪽 **QR 코드**를 방송 화면에 띄우거나, **참가 링크 복사**로 채팅에 뿌리기
3. 시청자는 링크 → 닉네임 입력 → 참가 완료
4. 문제가 뜨고 15초 뒤 자동으로 정답 공개 → **Space** 로 다음 문제
5. 35문제가 끝나면 **최종 순위 시상대** + 누적 명예의 전당

### 채팅에 쓸 안내 멘트 예시

```
유하경 능력고사 시작합니다!
👉 [참가 링크]  ← 클릭 → 닉네임 입력 → 참가
문제당 15초, 정답은 자동 채점됩니다. 폰으로 참가하세요!
```

### "새 라운드" vs "새 방" — 헷갈리기 쉬운 두 버튼

| 버튼 | 세션 코드 | 참가자 | 링크 | 언제 쓰나 |
|---|---|---|---|---|
| **새로 시작하기** (로비 / 최종화면) | 그대로 | **그대로 유지** (점수만 0으로) | 그대로 | 같은 사람들과 한 판 더 |
| **새 방 만들기** (로비 / 설정) | **새 코드로 변경** | **전원 퇴장** (기존 방 닫힘) | **새 링크 다시 배포** | 방송을 새로 시작, 참가자 싹 리셋 |

- **새 방 만들기** 를 누르면 기존 방에 있던 시청자 화면에 즉시 **"방이 닫혔습니다 → 새 링크로 들어오세요"** 가 뜹니다.
  (그 방의 응답 데이터도 함께 삭제됩니다)
- 차단(kick) 목록도 방마다 따로라, 새 방에서는 **전원 다시 입장 가능**합니다.
- 시청자 닉네임은 브라우저에 기억되어, 새 링크를 누르면 **닉네임 입력 없이** 바로 들어갑니다.

### 문제당 시간(타이머) 바꾸기

**설정 (S) → 문제당 시간** 에서 초를 정합니다. (기본 15초, 5~120초)

- 빠른 선택 버튼: `10초` `15초` `20초` — 직접 숫자를 입력해도 됩니다
- 변경하면 **다음 문제부터** 적용됩니다 (진행 중인 문제는 그대로)
- 이 값은 DB의 `state.seconds` 로 저장되어, **서버 규칙이 그 시간으로 응답을 마감**합니다
  → 10초로 바꾸면 10초 뒤 제출은 자동 거부되고, 참가자 화면 카운트다운도 10초로 표시
- 브라우저별로 저장되므로, 방송하는 PC에서 한 번만 설정하면 계속 유지됩니다

### 단축키 (호스트)

| 키 | 동작 |
|---|---|
| **Space** | 시작 / 정답 공개 / 다음 문제 |
| **R** | 처음부터 (로비로) |
| **F** | 전체화면 (OBS 브라우저 소스에 좋음) |
| **S** | 설정 |

### 그 밖의 기능
- **이어하기**: 방송 중 새로고침해도 로비에 `이전 라운드가 있습니다 → 이어서 하기` 버튼이 뜹니다. 점수/진행 상황이 DB에 있어서 복구됩니다.
- **내보내기(×)**: 참가자 목록에서 `×` → 그 사람은 이 코드로 다시 들어올 수 없습니다.
- **O / X**: 정답 공개 화면에서 채팅으로만 답한 사람을 수동 채점 (O = 500점)
- **CSV 저장**: 최종 화면에서 순위표 다운로드
- **명예의 전당**: 라운드가 끝날 때마다 `alltime`에 누적 (같은 브라우저 = 같은 참가자로 집계)

## 3. 점수 규칙 (속도 무관 · 정답 개수)

- 정답: **1점** — **속도 보너스 없음** (빠르게 찍어도 늦게 찍어도 동일)
- 오답/미응답: 0점
- 제한 시간(15초)은 **서버가 판단**해서 넘으면 응답 자체가 거부됨 → 시간은 점수에 영향 없음
- 동점 → 이름 순
- 점수 단위는 `js/questions.js` 의 `pointsPerCorrect: 1` 로 변경 가능 (예: 10점으로 하면 정답당 10점)

**최종 화면은 참가자 전원 중 상위 3명(시상대)만 표시**합니다. 전체 순위는 `CSV 저장` 버튼으로 받을 수 있어요.

## 4. 문제 수정하기 (`js/questions.js`)

```js
{
  part: 'Part 1 · 기본 프로필 & 신체 TMI',   // 화면 상단 파트 표시
  q: '유하경의 생년월일은?',                  // 질문
  options: ['1998년 11월 24일', '1999년 12월 24일', '1999년 11월 24일', '2000년 11월 24일'],
  answer: 3                                  // ★ 정답 번호 (1부터 시작 = 3번째 보기)
}
```

- `answer` 는 **1부터** 셉니다.
- 보기는 4개 또는 5개 모두 가능 (마지막 문제가 5개)
- 문제 수를 바꾸면 `Q1 / 35` 표시도 자동으로 따라갑니다
- 제한 시간 기본값은 파일 맨 위 `seconds: 15` 이고, **사이트 설정의 "문제당 시간"이 우선**합니다

### 현재 정답 배치 (정답이 2번에 몰리지 않게 보기 순서를 섞음)

원본 정답지가 거의 전부 `2번`이어서 보기 순서를 섞어 정답 번호를 분산했습니다.
정답 **내용**은 원본과 동일합니다. (1번 9개 / 2번 9개 / 3번 8개 / 4번 8개 / 5번 1개)

```
Q1:3 / Q2:1 / Q3:4 / Q4:2 / Q5:1 / Q6:3 / Q7:2 / Q8:4 / Q9:3 / Q10:1
Q11:4 / Q12:2 / Q13:1 / Q14:3 / Q15:2 / Q16:4 / Q17:1 / Q18:2 / Q19:4 / Q20:3
Q21:1 / Q22:5 / Q23:2 / Q24:4 / Q25:1 / Q26:3 / Q27:2 / Q28:1 / Q29:4 / Q30:3
Q31:2 / Q32:4 / Q33:1 / Q34:3 / Q35:2
```

방송 전에 한 번 확인하고, 다르면 `js/questions.js` 의 `answer` 숫자만 고치면 됩니다.
(원본에서 살짝 의아한 항목: Q25 `변명`, Q30 `20분/30분`, Q32 `시청자/55%` — 원본 정답지를 그대로 따랐습니다)

## 6. 자주 묻는 질문

**Q. `apiKey` 가 링크에 그대로 들어가는데 위험하지 않나요?**
아니요. Firebase 웹 API 키는 원래 공개되는 값입니다(모든 Firebase 웹사이트에 들어 있음).
실제 보호는 **4단계의 보안 규칙**이 담당합니다. 대신 **서비스 계정 비공개 키 JSON**(`type: service_account` 로 시작하는 파일)은 절대 붙여넣거나 공개하면 안 됩니다.

**Q. 무료인가요?**
네, Firebase 무료(Spark) 요금제로 충분합니다. 30명이 35문제를 풀어도 사용량은 아주 작습니다.

**Q. 몇 명까지 되나요?**
무료 기준 동시 접속 100명 정도까지 여유롭습니다. (문제당 응답 100개 수준은 문제없음)

**Q. 매 방송마다 코드를 바꿔야 하나요?**
새 판으로 시작하려면 설정에서 **세션 코드**를 바꾸는 게 깔끔합니다. 같은 코드로 `새로 시작하기`를 눌러도 초기화되지만, 명예의 전당은 계속 누적됩니다.

**Q. QR 코드가 안 되거나 안 보여요.**
1. **`localhost` / `file://` 주소는 폰에서 열리지 않습니다.** QR이 가리키는 주소가 그 PC 전용이라 그래요.
   → 폰으로 테스트하려면 PC의 IPv4(`ipconfig`)로 접속하세요: `http://192.168.0.12:8000`
   (같은 와이파이 + `python -m http.server 8000` + 윈도우 방화벽 8000 허용)
   → 실제 방송은 GitHub Pages 주소에서 하면 QR이 자동으로 인터넷 주소가 됩니다.
2. QR 이미지는 외부 서비스(qrserver → quickchart 순서로 시도)로 그립니다. 두 곳 다 차단되면 QR이 숨겨지고
   **참가 링크 복사** 안내가 뜹니다. 이때는 링크를 채팅에 올리세요.
3. QR을 클릭하면 **원본 크기(420px) 새 탭**으로 열립니다. 방송 화면에 크게 띄울 때 사용하세요.

**Q. 시청자가 링크를 못 열어요.**
참가 링크에 `?s=코드&db=...&k=...` 가 다 들어 있어야 합니다. **참가 링크 복사** 버튼으로 나온 링크를 그대로 쓰세요. (주소를 손으로 줄이면 안 됩니다)

**Q. 로컬 모드는 뭐예요?**
Firebase 없이 **같은 브라우저 탭끼리만** 테스트하는 모드입니다. 실제 시청자 참가는 Firebase 모드에서만 됩니다.

**Q. 방송 중 연결이 끊기면?**
오른쪽 위 상태가 `재연결 중…` 으로 바뀌고 자동으로 다시 붙습니다. 점수/진행 상황은 DB에 있으니 새로고침해도 **이어하기**로 복구됩니다.

**Q. `익명 로그인이 꺼져 있습니다 (OPERATION_NOT_ALLOWED)` 가 나요.**
Firebase → **Authentication → Sign-in method → Anonymous** 를 **사용 설정** 하세요. (1단계 5번)

**Q. 설정 코드에 `databaseURL` 이 없어요 / "DB 주소를 찾지 못했습니다" 가 나요.**
Realtime Database 를 아직 안 만들었을 가능성이 큽니다. **빌드 → Realtime Database → 데이터베이스 만들기** 후
설정 코드를 다시 복사해서 붙여넣으세요. (앱이 projectId 로 자동 탐색도 시도합니다)

**Q. 규칙을 넣었더니 `Permission denied` 가 나요.**
`hostUid` 가 이미 다른 계정으로 등록된 코드일 수 있습니다. 설정에서 **세션 코드를 바꾸고** 다시 연결하세요.

**Q. 설정 코드를 남에게 보여줘도 되나요?**
`apiKey` / `appId` 는 공개되는 값이라 괜찮습니다. 하지만 **`type: "service_account"` 로 시작하는 비공개 키 JSON** 은 절대 공유하면 안 됩니다.

## 7. 음악 테스트 (1초 듣고 노래 맞추기)

같은 Firebase·같은 링크 방식으로 동작하는 **주관식(타이핑) 퀴즈**가 따로 있습니다.

| | 주소 |
|---|---|
| 진행자(호스트) | `musictest.html` — 퀴즈 화면 우상단 **음악 테스트** 버튼 |
| 시청자(참가자) | 사이드바 **참가 링크 복사** → `musicplay.html?s=...` |

### 진행 방식
1. 호스트 화면에서 **새로 시작하기** (Space)
2. 문제가 뜨는 순간 **1초 클립이 자동 재생**됩니다 (부족하면 **▶ 1초 듣기** 버튼으로 다시)
3. 시청자는 폰에 **곡 제목을 타이핑**해서 제출 (한 문제에 1번만)
4. 시간이 끝나면 **정답 공개 + 앨범 커버 표시**
   - `answers` 를 비워두면 → 진행자가 공개 화면에서 **정답을 입력하고 "채점하기"** 를 누르는 순간 전원 채점
   - `answers` 를 채워두면 → 자동 채점 (공백·문장부호 무시, 부분일치 허용)
   - 틀린 사람은 채점표의 **O / X** 로 바로 고칠 수 있습니다
5. 마지막엔 **TOP 3** 시상대 + CSV 저장

> **추천**: 곡 제목은 진행 중에 입력하는 게 편합니다. `답`이 여러 개일 수 있으니
> `answers` 에 `['Dynamite','다이너마이트']` 처럼 넣어두면 자동 채점이 더 정확해집니다.

### 파일 구조

```
audio/1.mp3 ... 15.mp3     문제별 음원 (진행자가 트는 곡)
images/1.jpg ... 15.jpg    문제별 앨범 커버 (정답 공개 때 표시)
images/bg.png              로비에 뜨는 포스터
js/music-questions.js      ★ 문제/음원/커버/정답 설정
```

### 문제 설정 (`js/music-questions.js`)

```js
{
  q: '이 곡의 제목은?',
  audio: 'audio/1.mp3',     // 재생할 파일
  start: 0,                 // 재생 시작 위치(초) — 후렴부터 듣게 하려면 예: 32
  image: 'images/1.jpg',    // 정답 공개 때 보여줄 커버
  answers: [],              // 비우면 진행자가 공개 화면에서 직접 채점 (추천)
  note: ''                  // 정답 공개 때 함께 보일 설명(가수/연도 등)
}
```

맨 위에서 전체 설정도 바꿀 수 있습니다:

```js
clipSeconds: 1,        // 한 번에 들려주는 길이(초)  ← 1초 챌린지
seconds: 15,           // 문제당 제한 시간 (설정 창에서도 변경 가능)
pointsPerCorrect: 1,   // 정답 1개당 점수
poster: 'images/bg.png' // 로비 포스터
```

- `start` 를 곡마다 다르게 넣으면 "후렴 1초" 같은 재미있는 문제를 만들 수 있어요
- 음원이 커서 저장소가 무거워집니다(15곡 약 138MB). 필요하면 비트레이트를 낮춰(128kbps) 다시 넣으세요

### 퀴즈랑 방이 섞이지 않아요
- 두 앱은 **세션 코드를 따로** 기억합니다 (`hg.code.quiz` / `hg.code.music`)
- Firebase 설정(URL·API 키)은 **공유** — 한 번만 붙여넣으면 둘 다 연결됩니다
- 보안 규칙도 **추가 게시 불필요** (음악 테스트도 같은 `answers` 구조 사용)

## 9. DB 구조 (개발자용)

```
sessions/<CODE>/
  hostUid          "호스트 uid"                    (최초 1회)
  meta             { title, seconds, total, createdAt }
  state            { phase, qi, startedAt, seconds, correct, ts }   ← 정답은 공개 시점에만
  players/<uid>    { name, joinedAt, seen }
  banned/<uid>     { name, at }
  results/q<qi>/<uid> { ok, pts }                  ← 문제별 채점 결과
  scores/<uid>     { name, score, correct }
  final            { at, rank:[{uid,name,score,correct}] }

answers/<CODE>/q<qi>/<uid> { opt, at, n }          ← 호스트만 읽기 (참가자 답 숨김)

alltime/<uid>      { name, score, correct, games, best, code }
```

- 모든 시각 값은 `{".sv":"timestamp"}` (서버 시각)로 저장
- 호스트는 `sessions/<CODE>` 를 **SSE 스트림**으로 구독, 응답은 0.7초 간격으로만 조회
- 참가자는 같은 스트림에서 `state / players / scores / final` 만 받음
